## Webhook 是什么

Webhook 是一种通过 HTTP 请求传递事件通知的机制。接收方提供一个 URL，发送方在事件发生后，把相关数据发送到这个地址，通常使用 POST 请求。

可以把它理解成：你给对方一个通知地址，发生事情时，对方就主动把消息送过来。这样，接收方不需要反复询问“有没有新消息”。

在飞书自定义机器人里，Webhook 就是机器人的专属消息投递地址。你的程序把消息内容发送到这个地址，飞书验证请求后，机器人便会在所属群聊里发出消息。

## 飞书机器人如何使用 Webhook

以“测试完成后自动通知群聊”为例：

```text
测试运行完成
    ↓
你的程序组织通知内容
    ↓
向飞书机器人的 Webhook 地址发送 HTTP POST 请求
    ↓
飞书校验请求，并把消息发到对应群聊
```

在群里添加自定义机器人后，飞书会生成类似这样的地址：

```text
https://open.feishu.cn/open-apis/bot/v2/hook/xxxxxxxx
```

向这个地址发送一条文本消息，请求体可以写成：

```json
{
  "msg_type": "text",
  "content": {
    "text": "测试完成：共执行 100 个用例，全部通过。"
  }
}
```

其中，`msg_type` 表示消息类型，`content.text` 是群里显示的文字。下面是请求示例，需要把地址替换成实际的 Webhook 地址：

```bash
curl -X POST 'https://open.feishu.cn/open-apis/bot/v2/hook/xxxxxxxx' \
  -H 'Content-Type: application/json' \
  -d '{"msg_type":"text","content":{"text":"测试完成：共执行 100 个用例，全部通过。"}}'
```

这个示例只展示基本消息格式。如果机器人配置了关键词、IP 白名单或签名校验，请求还需要满足相应条件；启用签名校验时，需要额外生成并传入 `timestamp` 和 `sign`。

自动化逻辑由调用方负责：测试程序决定何时发送通知，Webhook 负责接收请求并触发群消息。自定义机器人本身不会运行测试，也不能接收并回复群成员的消息。需要对话能力时，应使用应用机器人。

## Webhook 和 SSE 的区别

Webhook 不是 SSE。SSE（Server-Sent Events，服务器发送事件）让客户端先建立连接，再通过持续打开的 HTTP 响应接收服务器推送的数据。

| 对比项     | Webhook                                            | SSE                                              |
| ---------- | -------------------------------------------------- | ------------------------------------------------ |
| 通知方式   | 发送方向接收方的 URL 发起 HTTP 请求                | 客户端先连接，服务器在同一个响应流里持续发送事件 |
| 连接使用   | 每次通知通常对应一个独立请求，无须维持长期订阅连接 | 保持流式连接，以便持续接收事件                   |
| 接收方要求 | 提供发送方能够访问的 HTTP 接口                     | 能主动连接服务器并读取事件流                     |
| 常见用途   | 支付结果回调、代码提交通知、飞书群通知             | 网页实时状态更新、日志流、AI 文本流式输出        |

两者的区别在于请求和数据传递方式，不能简单理解为“短连接”和“长连接”：Webhook 的多个请求也可以复用底层连接。

对应到飞书的例子，方向是“你的程序 → 飞书 → 群聊”。每次需要发群消息时，你的程序调用一次 Webhook 即可，无须像 SSE 那样持续接收一个事件流。
